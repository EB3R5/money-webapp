## [0.1.0] — 2026-10-15

The first public release: Django + SQLite, the SimpleFIN feed, household accounts. Everything below was built between 2026-09-21 and today on the way from the first build.

### ✨ Features
- **2026-10-14** — A fresh database also gets its balance-sheet and inventory taxonomies: `manage.py init_store` writes about forty account categories (Assets, Liabilities, Equity; the Add-account presets among them) from `app/seeds/account_categories.json` and about thirty inventory categories with their subcategory and classification lists from `app/seeds/inventory_categories.json`, each only when its own table is empty. The Balances and Inventory pickers and the Categories page's three tabs are populated from the first start
- **2026-10-08** — Settings → Users (#233), admins only: the members with role and last sign-in, the open invitations and pending reset links; mint an invitation or a reset link (shown once), revoke, deactivate (signs the member out everywhere) or reactivate, make or unmake an admin — the last admin cannot be removed; every action lands in the admin log; the Django admin is no longer the only door
- **2026-10-08** — The internet-exposure guide (#232): README's "Running on the internet" and the host-side checklist in `docs/deployment.md`, tried against a fresh container behind Caddy; `TRUSTED_PROXIES` names the reverse proxies whose `X-Forwarded-For` the login rate limiter believes (loopback always), so a proxy in another container does not put every visitor in one lockout bucket; the security doc's threat model now covers a public deployment behind TLS
- **2026-10-08** — The ML model's empty state (#230): with no model file the Categorization page's model tab says so and counts the categorized transactions a retrain needs, the Ledger's ML suggest button is disabled with the reason, and the suggest panel says there is no model; `/api/ml/model` reports `trained` and `labelled_rows`; the first retrain switches everything on at the next page load
- **2026-10-08** — A fresh database gets a starter taxonomy (#229): `manage.py init_store` writes about fifty Categories with their derived fields from `app/seeds/categories.json` when the table is empty, and never touches one that has rows; the Ledger dropdown, the Categories page and the budget editor's group picker are populated from the first start
- **2026-10-08** — Settings → Feed (#228): the SimpleFIN feed's state on one page — configured or not, today's request budget, the last run, the cursor, the next scheduled run — and, until it is set up, the exact claim command and where the Access URL goes; the credential stays in the environment and never reaches the browser. A Settings menu in the nav (Feed, Account); the Activity page links here
- **2026-10-08** — Per-user API tokens (#226): named, minted on `/account` or with `manage.py api_token`, shown once, hashed, revocable; a request with `Authorization: Bearer <token>` acts as that user without a session or a CSRF token, an unknown or revoked one is 401 at once; `POST /api/software/import` is the first consumer, so an exporter script can post its run
- **2026-10-08** — Remember me on the login form (#224): ticked, the session lasts thirty days instead of a day; logout and a revoked session row end it either way
- **2026-10-08** — Admin-generated password reset links (#231): `/admin/` (Access links, kind Password reset) or `manage.py reset_link <user>` mints a one-time, one-day link, shown once; `/reset/<token>` sets the new password, signs that account's other sessions out, forgives its login lockout and signs it in; the login page says to ask your admin
- **2026-10-08** — Invitation links, the only way to sign up (#225): an admin mints a link in `/admin/` (Access links) or with `manage.py invite` — expiry, a use count, a note; shown once, stored as a hash — and the register page it opens (`/register/<token>`) creates a regular member of the household, signed in at once; a closed or unknown link is a plain 404; links can be revoked
- **2026-10-08** — First-run setup form (#223, open-source readiness #222): with no account in the database, `/login` sends you to `/setup`, a one-time form to choose the admin's username and password (validators, rate limit, CSRF; closed for good once a user exists). `DEFAULT_USER` / `DEFAULT_PASSWORD` no longer default to `changeme`: set both for a headless first account, else nothing is created
- **2026-10-06** — Year plan follow-ups: per-goal balances and a monthly contribution on the Savings page (#182); planned spend folds into the month's budget lines (#183); a movable twelve-month window and Calendar drag-and-drop (#184); reconciliation of planned spend to ledger rows with the matched rows netted out of the variable rate (#181, #185); the Pull now reads every open future-purchases item with a cost (researching or decided, status shown; ADR-0023 amended twice) instead of decided only; and an instant search box on the Year plan, Calendar, Projected P&L and Income pages (`search.js`, the one rule shared with the card boards)
- **2026-10-05** — Year plan (`Planning ▾`, ADR-0023): the Income sources registry generalised into **Expected flows** (`expected_flows`, migration 0017: kind income|expense, cadences once/bimonthly/semiyearly, placement by date or month, a Group, a savings goal, an origin) and twelve months of **planned spend** as three pages — the Year plan (`/planning/year`: a timeline of pins with funding bars, each month's net after planned spend, a detail card whose "Move to" buttons warn when a month would go negative, the shelf of unplaced items, an add/edit form), the Projected P&L (`/planning/projected`: the current month actual and eleven projected columns with one Planned row per Group, built on the pivot helper; the P&L page stays actual) and the Calendar (`/planning/calendar`: month cards, click-to-place from the shelf, a funds panel); placed items are dated outflows in the 90-day forecast; **Pull** (`POST /api/planning/sync/future-purchases`, the Sync button, an Activity feed column and form): future-purchases' read-only planned export read on demand, upserted by business id, hand edits winning per field, withdrawn items deactivated, never scheduled; `FUTURE_PURCHASES_URL` unset = off; savings goals accept a `monthly_contribution`
- **2026-10-05** — Planning section (`Planning ▾`, ADR-0021): three layouts of one month's facts over one Journal entry per period — the Month page (`/planning/month/{YYYY-MM}`: income, spend vs budget, net, net savings rate and Net worth tiles, Budget-vs-Actual with status pills, income expected vs received per Recurring series, the entry beside them with its figures frozen at first save and Prompt chips the data writes), the Notebook (`/planning/notebook/{period}`: the entry as a document with Figure blocks at `[[figures]]` / `[[misses]]`, a month rail, year reviews, a Write mode with live preview) and the Planner (`/planning/planner/{YYYY}`: a year strip with expected months, the 90-day Checking forecast, expected income for the year, sinking funds from the savings goals, the entry as a drawer); `journal_entries` (migration 0015) and `POST /api/planning/entry/{period}` (+ `/refreeze`, `/delete`, audited); `GET /api/planning/forecast`; net worth now has one owner (`app/networth.py`, the Balance Sheet reads it); every derived number is labelled "estimated from ledger"
- **2026-10-04** — Uploads in the database (ADR-0020): photos of Items, Software and Kits and the bytes of file Documents are rows of `blobs`, keyed by the photo entry id or the document id, so `money.sqlite` alone holds every upload (the ML model stays a file); a Blob outlives its owner so a row restored from `deletions` finds its bytes; `scripts/move_files_into_db.py` moves an existing data directory once (dry-run by default, sha-verified, idempotent; runbook `docs/runbooks/uploads-into-db.md`) and `scripts/prune_blobs.py` removes Blobs no live row or deletion snapshot references, then VACUUMs
- **2026-10-03** — Kits (`/kits`, Inventory ▾, ADR-0018): a named set of Items and Software that serve one purpose, with a description, a Markdown how-to, its own photos and Documents; one page per Kit with a cover hero, the photo grid of every member and a transfer list that saves each move (`POST /api/kits/{id}/members`); only active software counts toward a Kit's `$/mo`; an Item's and a Software's modal show read-only Kit chips and the Item sheet a Kits row; `item.md` front matter lists `kits:`; `scripts/seed_kits.py` seeds Kits from `scripts/kits-seed.json` (the seven prototype kits), idempotent by name
- **2026-09-30** — Software board (`/software`, Inventory ▾, ADR-0017): the software you have as cards grouped by Status, Kind or Category with the monthly subscription cost as the board total; registry facts (latest version, stars, licence, repo, install locations) read-only in the modal; `POST /api/software/import` upserts one host's installed-software run on Source_Key from an **Import run** strip; `POST /api/software/{id}/facts` writes the registry-owned fields
- **2026-09-30** — Software clipper: a bookmarklet for GitHub, PyPI, npm, App Store, Homebrew and any pricing page (registry JSON server-side, Open Graph + SoftwareApplication harvested in the browser); the clip popup is now one shared page for every clipper, and a **Clippers** page (`/clippers`) hands out all bookmarklets (`/inventory/clip/setup` redirects there)

### 🐛 Fixed
- **2026-10-14** — A Journal entry of the current month showed the figures from the day it was first written for the rest of the month (ADR-0021, amended): while a month or a year is still open its entry shows the live figures and has no Refreeze; the first save after the period ends freezes them. An entry frozen while its month was still open goes back to live on its next save
- **2026-10-08** — Signing in over HTTPS: the `Referrer-Policy` is `same-origin` instead of `no-referrer`. Under `no-referrer` a browser sends `Origin: null` on every form and fetch POST, and Django's CSRF check behind `tailscale serve` rejected the login with a 403. Nothing is sent to other sites either way; the tests now exercise the HTTPS path with the browser's Origin
- **2026-10-04** — Ledger: Month follows the Date when a Date is edited inline or a row is added (`Grid.derive`); before, an added row had no Month and an edited Date left the old Month until the feed next saw the row
- **2026-10-03** — Ledger edits on bank-fed transactions were reverted by the next SimpleFIN run (ADR-0019): each feed row now keeps the feed's last-applied value per provider field (`_provider`, migration 0013), a run writes a field only when the bank changed it and the person has not — a hand edit wins for good — and reports `hand edits kept`; pending twins match on the bank's values and carry the person's edits; a non-numeric Amount typed into the grid is refused instead of saved as blank, and a failed save now says so in the toolbar
- **2026-10-01** — Balance Sheet month picker (and the P&L, Tax, Savings and Health period pickers, and the Inventory overview Print button) did nothing in the browser: their inline `onchange`/`onclick` handlers were blocked by the nonce-only CSP. One page-wide `ui.js` submits a `.year-picker` form on change and prints on `[data-print]`; the balance sheet route accepts the picker's `?ym=YYYY-M`; the security tests now reject any inline event handler in a template
- **2026-09-30** — The status filter on card boards (Accounts, Inventory) now works in the browser: its handler moved out of an inline `onchange` the nonce-only CSP was blocking; the clip popup's harvested thumbnails now preview (the popup carries its own CSP with `https:` images)

### 🔄 Changed
- **2026-10-14** — Nothing of one household left in the code: the Credit page keeps the score tracker, the FICO bands and factors, the what-if scenarios and the payoff planner, and drops the card recommendations and the advice list that were written for one person; the Tax page estimates state tax from one effective rate the person enters instead of a hardcoded state's brackets; a holding is cash when its name says so, not when it names one fund; the savings-category default also knows the starter taxonomy's `Investment`; test fixtures use neutral account and holding names
- **2026-10-14** — The columnar pad: one visual identity for the whole app, drawn from the accountant's ruled pad. Pale ledger-green paper with a sheet laid on it, one vertical column rule the full height of the page with the navigation in the stub beside it (groups fold; the current page's group is open), Literata for page titles and the Notebook's prose, Atkinson Hyperlegible with tabular lining figures for everything else, red ink only for money out and bank green for money in. Regions are ruled rather than boxed, table headers are a rule not a filled band, charts follow the same type and ink. Both faces are vendored (`app/static/vendor/fonts`): nothing loads from a third-party origin
- **2026-10-08** — One public URL (#227): `BASE_URL` is the origin the app is reached on — the request hosts Django accepts, the origins its CSRF check trusts, what the clipper bookmarklets and the invitation / reset links bake in. `CLIP_BASE_URL` is the old name: it still works and warns at start
- **2026-10-08** — The app is Django only (ADR-0024 accepted; slice 9 of #199): the image collects static files at build and its entrypoint applies the schema, the migrations and the first account before gunicorn; the reference `compose.yml` and the homelab stack run `money-next-jobs` from the same image; the desktop launcher starts Django's server; `docs/deployment.md`, `docs/SECURITY.md` (CSRF, headers, the 411 rule, the redaction at the record factory, Django's tables in the data file), the README and `packaging/README.md` describe the Django build; `docs/runbooks/django-cutover.md` is the production cutover
- **2026-10-08** — SimpleFIN endpoints and the Clippers page on Django (slice 8 of #199), and the scheduler leaves the web process: `manage.py run_jobs` runs the feed's cron and catch-up jobs plus a daily expired-session clean-up on a blocking scheduler, idling when no feed is configured; a run in progress in the other container counts as busy (a recent `sync_runs` row still marked running, committed as soon as it is written), so Sync now and the scheduled run never overlap; the last two FastAPI routers removed
- **2026-10-08** — Tax, Credit, Health analysis, Investments, Balances, the Data page and Activity (with `/api/health`) on Django (slice 7 of #199), same paths and JSON shapes; the Data page, its API and the store's table listing never show Django's own tables (`auth_*`, `django_*`, `money_*`); the eight tests parked by the two earlier slices run again; their seven FastAPI routers removed — only the Ledger's legacy grid, the SimpleFIN routes and the Clippers page remain on FastAPI
- **2026-10-08** — Dashboard, Category insights, Reports (P&L, Balance Sheet, Inventory overview and its sync), Planning (Month, Notebook, Planner, Income, Year plan, Calendar, Projected P&L and the entry / flows / pull / reconcile API), Budgets (full paths; the FastAPI router's prefix is gone) and Metrics on Django (slice 6 of #199), same paths and JSON shapes; the Planning Jinja filters live in `app/jinja_filters.py` on the shared environment; a `?next=` on the Planning form POSTs must be a local path; their six FastAPI routers removed
- **2026-10-08** — Card collections on Django (slice 5 of #199): `CardCollection` is a Django module (`urlpatterns()` replaces `router()`; uploads come from `request.FILES`), and Accounts (with the feed strip and archive/reopen), Inventory (board, taxonomy, Finder columns, clipper popup, Item sheet and bundle export), Software (board, facts, import, clipper), Kits and Documents (pages, raw bytes with their own frame headers, preview) serve at the same paths and JSON shapes; `/inventory/clip/setup` redirects to `/clippers` from the clip views; their ten FastAPI routers removed. Fixed-segment routes one segment past a board's slug are registered before the board, since Django matches by path alone
- **2026-10-08** — Categorization and Categories on Django (slice 4 of #199): `app/views/categorization.py` (the Rules editor, preview and test, Rule apply, ML suggest, the per-transaction suggest, model info and retrain) and `app/views/categories.py` (the lookup contexts) at the same paths and JSON shapes; their FastAPI routers removed
- **2026-10-08** — Accounts, Mealie-style (ADR-0024, slice 3 of #199): users live in `django.contrib.auth`; `manage.py bootstrap_admin` seeds the first admin from `DEFAULT_USER` / `DEFAULT_PASSWORD` (default `changeme`, a password change is forced at first sign-in on `/account`) or imports the legacy credential row with its password (a bcrypt hash, upgraded on the next login); `/login` is username + password with the same rate limiter (the TOTP second factor is gone); sessions are rows, so one can be revoked; `/admin/` adds users and sends its login to the app's form; `scripts/create_user.py` and `pyotp` removed
- **2026-10-08** — Django beside FastAPI (ADR-0024, slice 2 of #199): `manage.py`, `config/` (settings read from `app/config.py`, the URL root, the Jinja environment, a gunicorn config), `app/middleware.py` (security headers + CSP nonce, body limit with 411 for a chunked body, the Sec-Fetch-Site rule beside Django's CSRF, the auth gate, a per-request store scope that rolls back a failed request, the `DomainError` → JSON 4xx mapping), the Ledger as the first page on Django (`app/views/ledger.py`, `Grid.urlpatterns`), `manage.py init_store`, and the pytest-django harness (`tests/client.py`, a template-copied database per test, `legacy_client` for the FastAPI side). The hidden CSRF form field is Django's `csrfmiddlewaretoken`; the redacting log filter now runs from the log record factory. Plan: `docs/plans/2026-10-08-001-feat-django-port-plan.md`
- **2026-10-08** — The store layer is synchronous (ADR-0024, proposed): `aiosqlite` is gone, `app/store/database.py` opens plain `sqlite3` connections and `scope()` / `acquire()` are ordinary context managers; every store, domain, SimpleFIN and script function is a plain call, the feed's single-run lock is a thread lock, and `database.tables()` hides the `sqlite_` / `django_` / `auth_` / `money_` prefixes. FastAPI handlers stay async for now and simply call the stores; a `DomainError` raised by any operation is answered by one app-level exception handler instead of `guard()` catching it per call. First slice of the Django port (#200)
- **2026-10-04** — The image route serves a photo by its id from `blobs` (`kind=photo`; the per-table `with_photo` scans are gone); `app/store/files.py` is the model file only; the census counts photo entries over all three card tables and Blob rows under its `files` keys and adds a `blobs` section; the Data page hides `blobs`
- **2026-10-03** — Card boards: the modal is a shared partial (`_card_modal.html`); `CardCollection` gains `kits_enabled` (rows carry `_kits`, the delete cascade removes Kit memberships beside Documents), `template` and `page_context` (a page of its own over the same routes); `card-editor.js` gains `onCreated` / `onDeleted` hooks and exposes the Search rule's mirror as `window.searchTokens` / `window.searchHit`
- **2026-09-24** — Every section reads and writes the SQLite stores (ADR-0011): Balances, Registry/Credit, Tax, Savings, Health, Dashboard, Category insights, Reports, Categories, Accounts, Investments, Inventory (photos as files), and the Data page (`/data`, formerly Sheets)
